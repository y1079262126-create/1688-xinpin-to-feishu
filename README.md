# 1688 供应商新品采集 → 飞书多维表格

在影刀 RPA（ShadowBot）上运行的采集流程：自动打开 28 家（可扩展）1688 供应商店铺的
「新品专区」页面，抓取**产品链接 / 产品标题 / 产品图片 / 上新时间**，下载主图后写入
飞书多维表格，按天去重、可配置只保留最近 N 天。

- ✅ **基础账号可用**：全部逻辑在 4 个「插入代码段(Python)」里，主流程仅 4 行（上限 30 行）
- ✅ **纯标准库**：不需要在影刀里装任何 Python 包
- ✅ **免登录、免签名**：读取页面自己渲染的数据（DOM/React fiber），不逆向接口
- ✅ **防风控**：每店随机间隔 + 分批长休息 + 会话 cookie 重置 + 连续空手熔断
- ✅ **写入去重**：按「产品链接」三层去重，重复运行不会写重复数据
- ✅ **断点续跑**：抓取结果落盘 JSON，写入环节出问题可单独重跑

## 快速开始

### 1. 准备飞书自建应用

1. [飞书开放平台](https://open.feishu.cn/) 创建企业自建应用，开通 `bitable:app` 权限
2. 把应用**添加为目标多维表格的协作者（可编辑）**——漏了这步一定报 `permission denied`

### 2. 在影刀里建流程

1. 影刀新建「PC自动化应用」
2. 依次插入 4 个「**插入代码段(Python)**」指令，把 `S1~S4` 四个 `.py` 文件内容按顺序粘贴进去
3. 主流程共 4 行指令，远低于基础账号 30 行上限

### 3. 填配置（只在第 1 段）

打开第 1 段代码段，顶部总配置区：

```python
APP_ID     = "cli_填入你的AppID"
APP_SECRET = "填入你的AppSecret"
BASE_TOKEN = "你的多维表格 app_token"
TBL_SRC    = "源表 table_id"      # 供应商信息表（含「新品上新网址」「供应商名称」两列）
TBL_DST    = "目标表 table_id"    # 新品上新（下载）
F_LINK, F_TITLE, F_TIME, F_SHOP, F_IMG = ("产品链接", "产品标题", "上新时间", "供应商名称", "产品图片")
SRC_F_NAME, SRC_F_URL = "供应商名称", "新品上新网址"
```

### 4. 运行

- 启动时会弹框问**抓最近几天的上新**（直接确定 = 7 天，填 0 = 不限）
- 首次运行会自动清一次 1688 会话 cookie（过风控），跑通后可在第 2 段把
  `PURGE_COOKIE` 改为 `False`
- 全量 28 家约 25 分钟（限速防封）

## 二次修改指南

所有可变项都集中在**第 1 段总配置区**，其余三段自动复用：

| 想改什么 | 改哪里 |
|---|---|
| 换一张多维表格 | `BASE_TOKEN` / `TBL_SRC` / `TBL_DST` |
| 源表/目标表改了字段名 | `SRC_F_*` / `F_*`（目标表字段名同时用于中间数据和写入） |
| 抓取天数 | `DAYS_LIMIT`（第 2 段，0=不限） |
| 图片保存位置 | `IMG_DIR`（第 2 段，新电脑没有 D 盘就改 C 盘） |
| 抓取速度 | `DELAY_MIN/MAX`、`BATCH_SIZE`、`BATCH_REST`（第 2 段） |
| 主图张数 | 目前取主图 1 张；要抓多图改 S2 的 `pick_img` 返回列表 + S4 循环上传 |

改完只跑部分流程也可以：S3/S4 在检测到入参为空时会自动读取上次落盘的
`抓取结果.json`（双位置：`IMG_DIR` 和用户目录下的 `rpa_1688_img_backup`）。

## 常见问题

| 报错/现象 | 原因与处理 |
|---|---|
| `permission denied` | 应用没被加为多维表格协作者（可编辑） |
| `1254068 URLFieldConvFail` | 「产品链接」是超链接样式字段，代码已自动探测并按对象写入；若手动改坏可对照 S4 |
| 抓到 0 条且页面商品图只有 1 张 | 会话被 1688 风控标记。代码会自动清 cookie 换干净会话；仍不行就在影刀浏览器里手动登录一次 1688 |
| 抓到 0 条且商品图 0 张 | 检查 `IMG_DIR` 所在盘符是否存在；看 `诊断.txt` 里的 `url`/`imgs` 字段 |
| 「按天数过滤：保留 0 条」 | 表里的商品都比 N 天早。把 `DAYS_LIMIT` 调大或填 0 |
| 一条都没写进去 | 看批量写入失败的 `code`：链接字段格式 / token 不对 / 没加协作者 |

更多踩坑细节见各代码段头部注释（每一个坑都是实测换来的）。

## 工作原理

1. **S1** 飞书 API 读源表 → 供应商清单
2. **S2** 影刀浏览器（CEF，非 CDP，不易触发风控）逐店打开新品页 →
   监听页面自身请求（MTOP/JSONP）+ 读 React fiber 里的商品对象 + 滚动累加 →
   下载主图 → 结果落盘 JSON
3. **S3** 全局去重 + 按天过滤 + 按上新时间倒序
4. **S4** 主图上传飞书云空间 → 批量写入多维表格（file_token 缓存，重跑免重传）

> 1688 的商品卡不是 `<a>` 标签、div 上也没有商品 id，但 React 把商品数据挂在
> DOM 节点的 `__reactInternalInstance$xxx` fiber 上——顺着 `memoizedProps.data`
> 就能拿到完整商品对象。这是本项目 DOM 兜底路线的原理。
